# CSV → MD 字段映射

## description 推断优化

### 问题

`inferDescription()` 原本直接从正文全局取前 110 字（去 markdown 语法后拼接），当文章开头是个人信息元数据行时，生成的 description 不可用。

例如正文以如下内容开头：

```
个人信息：2024届/历史考生（历政生）/排位229/录取学校—南京大学/录取专业—社会科学试验班…
```

这段纯元数据被写入 frontmatter description，在文章卡片和搜索摘要中展示效果很差。

### 方案：三段式提取

按优先级依次尝试，命中即返回：

```
Tier 1: 模板"一句话总结" → 最精准
    ↓ 未命中
Tier 2: 跳过元数据行，取第一个实质性段落（≥ 15 字）
    ↓ 未命中
Tier 3: 兜底 — 全局取前 110 字（原行为）
```

#### Tier 1 — `extractSummaryLine()`

扫描正文行，定位"一句话总结"章节标题（如 `五、一句话总结（必填，50字以内）`），进入总结区块后跳过空行和引导短句（如"对未来想走这条路的学弟学妹说一句话："），提取第一条有效内容。

#### Tier 2 — 跳过元数据行

遍历正文每一行，通过 `isMetadataLine()` 跳过以下非叙述性行：

| 跳过规则 | 识别方式 |
|----------|----------|
| 模板章节标题 | `一、我的基本情况` `二、这条路的真实情况` 等 |
| 元数据前缀 | 以 `个人信息：` `基本情况：` 开头 |
| 高密度分隔符行 | 一行内 `/` `—` `：` `｜` 出现 ≥ 3 次且总长 < 150 字 |

跳过上述行后，取第一个长度 ≥ 15 字的行作为 description。

### 效果对比

| 场景 | 改动前 | 改动后 |
|------|--------|--------|
| 模板投稿（个人信息开头 + 有一句话总结） | `个人信息：2024届/历史考生…` | `先定专业再选学校，多查官网少信APP…` |
| 自由投稿（正常叙述开头） | `关于高考志愿填报之拙见 1.专业大于学校…` | `1.专业大于学校。目前特定高校title的光环已经远不如前…` |

### 涉及函数

| 函数 | 位置 | 说明 |
|------|------|------|
| `extractSummaryLine()` | `scripts/csv-to-md.mjs` | 从"一句话总结"区块提取正文 |
| `isMetadataLine()` | `scripts/csv-to-md.mjs` | 判断行是否为元数据/章节标题 |
| `inferDescription()` | `scripts/csv-to-md.mjs` | 三段式入口，优先级依次降级 |
